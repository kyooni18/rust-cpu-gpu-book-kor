## 화면을 그리는 장치에서 시작했습니다

**GPU**(graphics processing unit)는 이름 그대로 화면을 그리기 위한 전용 장치로 시작했습니다.
화면을 그린다는 것은 Full HD 기준 약 200만 개의 픽셀 각각에
거의 같은 계산을 적용해 색을 결정하는 작업입니다. 이 작업을 초당 60번씩 반복합니다.

픽셀 사이의 계산은 대부분 서로 독립적이므로 순서대로 처리할 이유가 없습니다.
GPU는 "같은 계산을 많은 데이터에 동시에 적용하는" 작업에 특화된 방향으로 발전했습니다.
이 구조가 행렬 계산이나 물리 시뮬레이션에도 그대로 활용될 수 있다는 점이 알려지면서,
GPU를 범용 계산에 사용하는 **GPGPU**(general-purpose computing on GPU)가 널리 쓰이기 시작했습니다.
현재의 머신러닝 분야도 이런 구조를 적극적으로 활용합니다.

Part I에서 살펴본 CPU의 고속화 기법인 분기 예측, 비순차 실행, 캐시는
"하나의 실행 흐름을 얼마나 빨리 진행할 것인가"에 초점을 맞췄습니다.
반면 GPU는 "동시에 진행하는 실행 흐름을 얼마나 많이 만들 것인가"에 초점을 둡니다.
이 차이를 중심으로 GPU의 주요 구조를 살펴보겠습니다.

- **CPU는 지연 시간 중심**(latency-oriented)입니다. 하나의 작업을 가능한 한 빨리 끝내기 위해
  분기 예측기, 비순차 실행 제어 구조, 대용량 캐시처럼 "계산 자체가 아닌 회로"에도
  많은 칩 면적을 사용합니다
- **GPU는 처리량 중심**(throughput-oriented)입니다. 개별 작업 하나는 느려도 괜찮으니
  단위 시간에 처리하는 전체 작업량을 최대화합니다. 제어 회로를 단순화하고
  남는 면적에 연산 유닛을 많이 배치합니다

대략적인 수치로 비교하면 성격 차이가 더 분명합니다.

| | CPU | GPU |
| --- | --- | --- |
| 연산 단위 | 수 개~수십 개 코어 | 수천~수만 개 레인 |
| 클록 | 3~5GHz | 1~2GHz |
| 스레드 하나의 속도 | 매우 빠름 | 느림 |
| 전체 연산 성능(f32) | 수백 GFLOP/s | 수 TFLOP/s 이상 |
| 분기 예측·비순차 실행 | 있음 | 기본적으로 없음 |

GPU의 개별 스레드는 분기 예측도 비순차 실행도 없는 경우가 많아서
Part I의 기준으로 보면 비교적 단순한 실행 환경입니다.
GPU의 높은 성능은 개별 스레드의 속도가 아니라 압도적인 병렬성에서 나옵니다.

## SIMT — 스레드를 묶어서 실행합니다

먼저 용어를 하나 구분하겠습니다. 여기서 말하는 "스레드"는 5장에서 다룬
운영체제가 관리하는 스레드와는 다른 개념입니다.
GPU에서 실행하는 프로그램을 **셰이더**(shader)라고 부르며,
계산 목적의 셰이더는 커널(kernel)이라고 부르기도 합니다.
GPU 스레드는 "셰이더 함수를 한 번 실행하는 흐름"을 뜻하는 매우 가벼운 논리 단위입니다.
WebGPU에서는 이를 invocation이라고 부릅니다. 운영체제가 직접 관리하지는 않습니다.

GPU의 스레드가 각자 완전히 독립적으로 실행되는 것도 아닙니다.
하드웨어는 약 32개 정도의 스레드를 하나로 묶어
**모든 스레드에 같은 명령어를 동시에 실행**시킵니다.
NVIDIA에서는 이 묶음을 **워프**(warp)라고 부릅니다.
WebGPU에서는 subgroup이라는 용어를 사용합니다.
실제 묶음 크기는 하드웨어마다 다르지만 32개가 대표적입니다.
이 실행 방식을 **SIMT**(single instruction, multiple threads)라고 부릅니다.

4장의 SIMD와 매우 비슷합니다. 실제 하드웨어도 넓은 벡터 연산기를 사용한다는 점에서는 비슷합니다.
차이는 프로그래밍 모델입니다. SIMD에서는 "스레드 하나가 벡터 레지스터를 조작한다"고 작성하지만,
SIMT에서는 "각 레인을 하나의 스레드처럼 보고 스칼라 코드를 작성한다"는 형태를 사용합니다.
11장에서 작성할 WGSL 셰이더가 바로 이런 방식입니다.

스레드를 묶어서 실행하는 대가가 **분기 발산**(divergence)입니다.
같은 워프의 스레드들이 `if`에서 서로 다른 경로로 나뉘면,
하드웨어는 보통 **두 경로를 차례대로 실행**합니다.
각 스레드는 자신과 관련 없는 경로가 실행되는 동안 마스크되어 기다립니다.
따라서 참과 거짓이 워프 안에서 섞여 있다면 양쪽 경로의 실행 비용을 모두 부담하게 됩니다.

3장에서 CPU는 "분기를 예측하고 결과가 나오기 전에 먼저 실행한다"고 배웠습니다.
GPU는 일반적으로 이런 방식 대신 같은 워프가 필요한 경로들을 순서대로 처리합니다.
두 구조 모두 **예측하기 어렵거나 스레드 사이에서 결과가 갈리는 분기는 비싸다**는 원칙은 같습니다.

## 지연 시간은 숨깁니다

GPU 메모리(VRAM)의 지연 시간은 수백 사이클 수준으로 CPU의 DRAM처럼 느립니다.
경우에 따라 더 느릴 수도 있습니다. GPU의 캐시는 CPU보다 상대적으로 작기 때문에
2장에서처럼 큰 캐시로 메모리 대기를 줄이는 전략만으로는 충분하지 않습니다.

GPU가 사용하는 방법은 **기다리는 동안 다른 워프를 실행하는 것**입니다.
실행 유닛 주변에 수십 개의 워프를 동시에 대기시켜 두고,
한 워프가 메모리 응답을 기다리게 되면 즉시 다른 워프를 실행합니다.
CPU의 SMT(5장)와 비슷한 발상이지만 규모가 훨씬 큽니다.
이 전환을 빠르게 하기 위해 GPU는 **상주 중인 모든 스레드의 레지스터 상태를
실제 하드웨어 레지스터 공간에 유지**합니다.

실행 유닛에 동시에 상주할 수 있는 워프의 하드웨어상 최대치와 비교해
실제로 몇 개의 워프가 상주하고 있는지를 나타내는 비율을 **점유율**(occupancy)이라고 부릅니다.
스레드 하나가 레지스터를 너무 많이 사용하면 동시에 상주할 수 있는 워프 수가 줄어들고,
점유율이 낮아져 메모리 대기 시간이 그대로 드러날 수 있습니다.
다만 점유율이 높다고 무조건 빨라지는 것은 아닙니다.
메모리 지연을 숨기기에 충분한 수준인지가 더 중요합니다.

이 구조에서 GPU의 중요한 조건을 하나 얻을 수 있습니다.
**GPU는 메모리 대기를 숨길 만큼 충분히 큰 병렬성이 있을 때 효과를 냅니다.**
수천 스레드 정도의 작은 작업에서는 실행 유닛을 충분히 채우지 못해
CPU보다 느린 경우도 흔합니다. 12장에서 실제로 비교합니다.

## 어떤 문제가 GPU에 잘 맞을까

지금까지의 구조를 바탕으로 GPU에 잘 맞는 문제의 조건을 정리할 수 있습니다.

- **데이터 병렬성이 높습니다** — 많은 원소에 같은 계산을 적용하고 원소 사이 의존성이 적습니다
- **문제 규모가 큽니다** — 수십만~수백만 개 이상의 작업이 있어 메모리 지연을 숨길 수 있습니다
- **분기 패턴이 비슷합니다** — 원소마다 실행하는 코드가 크게 달라지지 않습니다
- **다음 장에서 다룰 데이터 전송 비용을 감당할 만큼 계산량이 충분합니다**

행렬 연산, 이미지 처리, 물리 시뮬레이션, 신경망 계산은 이런 조건을 잘 만족합니다.
반대로 순차 의존성이 강한 파싱이나 상태 기계, 분기가 매우 많은 처리,
작은 데이터에 대한 작업은 대체로 CPU가 더 적합합니다.

## 용어 대응표

GPU 분야에서는 같은 개념을 API마다 다른 이름으로 부릅니다.
이 책은 다음 장부터 WebGPU와 WGSL 용어를 사용하지만,
다른 문서를 읽을 때 참고할 수 있도록 주요 용어를 비교해 두겠습니다.

| 개념 | WebGPU/WGSL | CUDA | Metal |
| --- | --- | --- | --- |
| 실행 흐름 하나 | invocation | thread | thread |
| 스레드 묶음(약 32개) | subgroup | warp | SIMD-group |
| 공유 메모리를 사용하는 그룹 | workgroup | thread block | threadgroup |
| 그룹 내부 공유 메모리 | workgroup memory | shared memory | threadgroup memory |
| 하드웨어 실행 단위 | (compute unit) | SM | GPU core |
| 전체 실행 요청 | dispatch | grid | grid |

저장소를 로컬에 내려받았다면 다음 명령으로 wgpu(11장)가 인식한

```sh

```

저자의 환경에서는 `GPU: Apple M4`라고 표시됩니다.
코드의 세부 내용은 11장에서 설명합니다.

## 정리

- GPU는 많은 데이터에 같은 계산을 높은 처리량으로 적용하기 위해
  제어 회로를 단순화하고 많은 연산 유닛을 배치한 계산 장치입니다
- GPU 스레드는 약 32개 단위의 묶음인 워프에서 같은 명령어를 실행합니다(SIMT).
  워프 안에서 분기가 갈리면 여러 경로를 순서대로 실행해야 해서 느려질 수 있습니다
- 메모리 지연은 큰 캐시보다 많은 워프를 빠르게 전환하는 방식으로 숨깁니다.
  따라서 충분히 큰 병렬성이 필요합니다
- GPU는 대규모 데이터 병렬 작업이면서 분기 패턴이 비교적 일정한 문제에 잘 맞습니다

다음 장에서는 GPU 성능에 직접적인 영향을 주는 메모리를 살펴봅니다.
VRAM, 공유 메모리, CPU와 GPU 사이의 데이터 전송을 다룹니다.
2장에서 배운 "데이터를 어떻게 배치하는가"라는 문제가 GPU에서는 더 중요하게 나타납니다.
